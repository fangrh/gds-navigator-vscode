# GDS Navigator for VS Code

A native VS Code extension for opening GDS layouts with **provenance-aware
source navigation** and **microscope-image overlay alignment** — ported from
[superGDS Studio](https://github.com/fangrh/overages) (the Overleaf-style web
GDS editor) into VS Code. The web app's Monaco editor, terminal and file tree
are dropped; VS Code itself provides those. What remains is the layout viewer,
the provenance navigation, the script runner and the image-registration tool.

## Features

### Layout viewer
- **Open `.gds` directly** — double-clicking any `.gds` file opens the GDS
  Navigator (OpenLayers canvas, pan/zoom, layer legend with per-layer
  visibility, click / ctrl-click / drag-box selection).
- **Draw tools** (rectangle/circle/line/polygon + snap) for quick measuring;
  drawn shapes are ephemeral.

### Provenance-aware source navigation
- **Automatic sidecar detection** — `chip.provenance.json` (written by the
  [fangrh/gdsfactory](https://github.com/fangrh/gdsfactory) fork when
  `GDS_PROVENANCE=1`) or plain `chip.json` next to the `.gds` is loaded
  automatically; provenance embedded in the GDS (TEXT layer 255/255 +
  properties) is also read.
- **Click a polygon** → selection detail (file:line, bbox, instance name,
  cell, loop/array indices, call chain) is written to the **GDS Navigator
  output channel** — the same text you paste to an AI agent.
- **Jump to source** and back: provenance links open the Python file at the
  exact line; `GDS: Select Features by Source Line` selects the layout
  features generated by the line under your cursor.
- **Loop/array index aware selection** — indices are zero-based,
  outermost-first, matching Python semantics: nested for-loops report
  `loop=(i,j)`, (nested) AREF arrays report `array=(col,row)` or
  `array=(outer)×(inner)`. **Ctrl+A cycles** an index ladder: one element →
  release the innermost index → … → whole placement line → clear.

### Build integration
- **▶ / `GDS: Rebuild Current Layout`** — runs the generating script (derived
  from the sidecar or appointed manually) with `GDS_PROVENANCE=1`, then
  auto-refreshes the viewer. The **no-sidecar flow**: open a GDS without
  provenance → click the *Provenance: OFF* indicator → appoint a `.py` →
  it is executed and the sidecar is generated.
- **Environment picker** — `GDS: Select Python Environment` lists conda envs;
  or set `gdsNavigator.pythonPath` (e.g. an isolated venv with the fork
  installed).

### AI-agent handoff
- **Copy Selection as YAML** (toolbar icon or `Ctrl+Shift+C`) puts a
  machine-readable summary on the clipboard:
  ```yaml
  mzi_example.py Component 1: Line 8, bbox:[5.5000, -1.1250, 15.5000, -0.1250]
    loop_index: (2,3)  # zero-based, outermost first
    call_chain:
      - @D:/proj/scripts/mzi_example.py#8 (<module>)
  ```

### Microscope image overlay + automatic alignment
- **Insert** a PNG/JPG photo of the fabricated chip (toolbar icon or
  `GDS: Insert Microscope Image`) — it overlays the layout at 55% opacity.
- **Fully automatic alignment** (crosshair button): the photo is registered
  against the layout with no manual pre-positioning:
  - Sobel edges with true non-maximum suppression on the photo; rasterized
    layout edges as reference.
  - **The layout is the reference**: photo content that does not exist in the
    GDS (2D-material flakes, contamination, bubbles) gets zero weight — a
    trimmed chamfer kernel plus gradient-orientation matching keeps foreign
    structures from biasing the fit.
  - Global multi-scale search → per-candidate refinement → scale/rotation
    sweep → hill-climb polish. A marker-pitch prior (autocorrelation) locks
    scale directly for periodic marker grids; small-FOV photos use a tiled
    translation search.
  - Result (position, µm/px, rotation, edge-match %, inlier fraction) is
    written to the output channel.
- **Manual fine-tuning**: image-move tool — drag, `Shift+wheel` scale,
  `R`/`T` rotate ±1°/±5°, arrows nudge 1/10 µm, `O`/`P` opacity.

## Requirements

| Capability | Needs |
|---|---|
| Viewing / zooming any `.gds` | Python env with [`klayout`](https://pypi.org/project/klayout/) (`pip install klayout`) |
| Provenance generation (sidecars, jump-to-source) | The [fangrh/gdsfactory](https://github.com/fangrh/gdsfactory) fork |

Pick the environment once with `GDS: Select Python Environment` or set
`gdsNavigator.pythonPath`.

## Usage

1. `File > Open Folder` on your layout project.
2. `GDS: Select Python Environment` → the env with klayout/gdsfactory.
3. Double-click a `.gds` file — pan/zoom, toggle layers, click shapes.
4. ▶ re-runs the generating script and refreshes the view.
5. Select shapes → `Ctrl+Shift+C` for AI-ready YAML.
6. Fabricated the chip? Insert its microscope photo and hit the crosshair
   button — the photo snaps onto the layout it came from.

## Development

```bash
npm install
npm run compile      # dist/extension.js + media/ol.js|ol.css (esbuild)
```

Press **F5** in VS Code to launch the Extension Development Host.

- `src/` — extension host (editor provider, env picker, runner, clipboard).
- `webview/viewer.html` — the viewer UI + alignment engine
  (`webview/ol-bundle.ts` bundles npm `ol` into `media/ol.js`; no CDN).
- `python/parse_gds.py` — GDS → GeoJSON + provenance merge (klayout.db).
- `scripts/make-standalone.js` — builds `webview/test-standalone.html`, a
  browser harness for the webview logic (serves the page with
  `python -m http.server`, load `?data=<fixture>`); fixtures in
  `test/fixtures/` are gitignored — drop your own GDS exports and photos
  there.

### Packaging

```bash
npm run package      # production build
npx @vscode/vsce package   # -> gds-navigator-0.1.0.vsix
code --install-extension gds-navigator-0.1.0.vsix
```
